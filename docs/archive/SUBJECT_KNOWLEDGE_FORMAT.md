# Reusable subject knowledge, format 1

The parent-owned JSON snapshot lives in each subject's **Subject Knowledge** folder. Its immutable name is `subject-knowledge-v1-<content fingerprint>.json`. Completed analysis and subsequent parent source reviews save a fresh snapshot automatically; **Save knowledge file** can retry if the synced folder was unavailable. Saving and assigning existing knowledge use no AI generation.

The envelope contains `content_sha256` and `contents`. The checksum is SHA-256 of UTF-8 JSON for `contents`, with sorted object keys and Python's default JSON spacing. The format marker is `homeschooling.subject-knowledge` and `format_version` is `1`. The checksum detects accidental modification; it is not a digital signature or evidence that AI proposals are correct.

Contents include subject and intended grade labels, collection and analysis versions, exact PDF SHA-256 fingerprints, source roles/editions/order/companions/key targets, section summaries, concepts and vocabulary, objectives, chronology, connections, original exercise identities, source citations, coverage and unresolved warnings. Parent source review history remains distinguishable from generated proposals. The `teacher_only` block contains raw scan units and private answer-key entries. This archive is a parent resource; it is never sent wholesale to student narration or guide generation. Original PDFs are separate and must be retained.

Child answers, assessment history, mastery claims, learning snapshots, personalized guides, session checkpoints, assignments, recordings and credentials are excluded. Subject and grade label the curriculum; matching source bytes and editions determine whether its analysis can be reused.

On the same home server, **Use saved subject knowledge** assigns a completed family collection to another subject and saves its knowledge file in the receiving subject's folder. Original PDF bytes are verified first. The existing collection/map/scans and source reviews are shared, with no new analysis request. Each subject chooses its own checked teaching portions and prepares its own guides. Existing learner records and started lessons are preserved. Reading topics are still assigned separately; this operation does not copy another child's completed curriculum or schedule.

Source corrections belong to the shared books and apply to all linked subjects. Changing a shared collection's book list or metadata creates a separate collection for the editing subject, retaining reusable scan caches and leaving the other subjects' sources unchanged. Choosing a collection that would replace different existing books is refused. Test-mode files and assignments stay in its isolated storage.

The JSON standard preserves the extracted source material outside the database for inspection and future migration. The current reuse UI uses registered collections on the same home server; it does not yet import arbitrary JSON into a new installation. Normal database restore plus the original PDFs remains the supported recovery path. Never share the parent archive as a student-facing download, because its teacher-only section can contain answers.
